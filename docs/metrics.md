## 指标口径

日志按会话读取：最初的 `rollout-…-<thread>.jsonl` 和经元数据核对的 `rollout-…-<thread>_<segment>.jsonl` 合并为同一会话。后续文件可能从 ordinal 0 开始，也可能通过 `history_base` 指向前一文件的字节位置和 ordinal；仅文件名相似不够。响应按 `response_id` 去重，上下文、缓存和速度使用续写后的读数。2026-10-25 已用 Codex Desktop `0.164.0-alpha.11.1` 的本地日志验证“空的中断首段 → 新段 → 引用前段的续写”这一格式；[App Server 文档](https://learn.chatgpt.com/docs/app-server#turn-events)中的 `thread/tokenUsage/updated` 是通知接口，插件实际读取本地持久化日志。

| 指标 | 计算方式 |
| --- | --- |
| 上下文占用 | 最近一次响应的 `total_tokens` ÷ `model_context_window`。按单次响应计算，**不是**整个对话的累计用量。压缩后显示「刚压缩」，下一次响应后才有新读数。 |
| 额度 | 会话日志里 `token_count.rate_limits` 的最近一次快照。窗口长度、重置时间都来自数据本身（例如 `window_minutes = 10080` 即 7 天），不假定「主窗口 = 5 小时」。显示读数时间；已过重置时间的读数会标明可能失效。**不是实时 API 查询。** 同账号的其他会话读数更新时，也会采用（并标注来源）。历史只在读数来自同一账号、同一额度（limit id 与窗口一致）且时间更晚时才接上；否则历史标为「本会话记录」，另注当前读数来自哪个会话。详情里的「时间进度」是窗口已过去的时间比例，只作时间参照，不是用量目标或服务承诺；窗口信息不全时不显示。 |
| 缓存命中 | 观测值：`cached_input_tokens` ÷ `input_tokens`。日志缺少 `cached_input_tokens` 时显示「未记录」，**不当作 0%**。「近 5 次」先求和再相除，只计入两项都有记录的响应，并写明「近 N 次中 M 次有记录」。 |
| 缓存保留 | 参照规则，不是观测：请求时间取这次响应第一个事件的 `started_at_ms`。GPT-5.6 及以后的模型按 OpenAI 规则至少保留 30 分钟（`prompt_cache_options.ttl`），面板在「保留参考」一行用一根随时间缩短的细条表示，右侧是剩余分钟，下方写「规则推算 · 最短至 HH:MM」；超过这个时长后显示「状态未确认 · 已超过最短保留时长」——日志不记录实际保留多久，缓存可能仍在，也可能已失效。没有公开规则的模型不画这一行，只注明没有公开的最短保留时长。缓存按模型分开：`thread_settings_applied` 换了模型后，下一次请求预计读不到原模型的缓存（未观测到的请求不当作已确定）。 |
| 费用 | 内置 API 价估算，公式与 [CodexBar](https://github.com/steipete/CodexBar) 相同：(输入 − 读取 − 写入) × 输入价 + 读取 × 缓存读取价 + 写入 × 缓存写入价 + 输出 × 输出价；`input_tokens` 是整个提示，读取与写入都是它的一部分，`reasoning_output_tokens` 已含在输出里。写入取日志的 `cache_write_input_tokens`。价目表只有一份，在服务器端 `server/desk_status/pricing.py`（2026-10-30，依据 [OpenAI API 价表](https://developers.openai.com/api/docs/pricing)），读入日志时逐次计价：按这次响应所属轮次的模型与档位取价：`default` / `standard` 为标准档，`priority` / `fast` 为 Fast，`ultrafast` 为 Ultrafast。GPT-6.1 Terra 收录标准和 Fast；GPT-6 Astra 与 GPT-6.1 Sol 另收录 Ultrafast 的完整费率（含缓存与长上下文，为标准档的 6 倍）。没有收录的模型或档位组合保留为未计价，不套用标准价。长上下文按各模型自己的规则（`long_above`，目前为 272K）判断**这次请求自己的**输入，超过时整次按长上下文价，没有长上下文价的模型不加价。总额、四部分、每次请求的费用柱与子代理合计都由这些逐次结果相加。日志缺少缓存用量（读取数，或单独计价的模型缺写入数）的请求按全部未缓存估算并注明——这是假设，不是上限或下限；缺少输入或输出用量的请求只计已记录的部分，金额标为「不完整」。多代理合计只要有线程未计价或用量不全，就写「已计价」而不是「全部 / 合计」。下次输入的两种情形：输入 = 本次输入 + 本次输出；「若命中」时本次输入按读取价、新增部分按输入价；「若未命中」时全部是未读到缓存的输入。未读到的部分按未缓存输入价，若同时写入缓存则按写入价（写入价单列的模型），两者构成区间。 |
| 输出速度 | 最近 5 次**有效**响应的 Σ`output_tokens` ÷ Σ用时（加权，不是算术平均），只计入与当前模型、推理强度**和速度档位**相同的响应（`priority` 与 `fast` 合并为同一档），从会话保留的全部样本里找，所以中间夹着很多无计时回复也不影响；柱图画同一设置最近 12 次有效回复，参与平均的 5 次都在图内，虚线就是平均值；按 `response_id` 去重，`token_count` 通知不重复计数。每次响应的用时 = 从上一个响应边界之后第一个 `Reasoning` / `AgentMessage` 的 `started_at_ms`，到本次 `token_usage_record` 的时间戳。包含推理与工具参数的生成；两次响应之间执行工具的等待不计入。这是**日志估算**，不等于模型纯解码速度。当前模型、强度与档位还没有样本时（例如刚切换速度），显示切换前最近一组设置的读数，并写明原模型、强度和档位，并标明「切换前」。 |
| 会话 / git | 会话 ID、模型、推理强度、开始时间、工作目录；git 分支与改动数来自只读的 `git status --porcelain=v2`（带超时，参数列表调用，不经 shell）。 |

费用是 API 标价估算，不能换算为订阅额度。按 [Codex 官方定价](https://learn.chatgpt.com/docs/pricing)，Ultrafast 的订阅内额度消耗为标准档的 8 倍，购买的 credits 为 6 倍；额度卡继续采用日志实际记录的账号快照，不根据 token 估算额度。
